# Swap-Online 完整方案

> 分支：`feature/online`
> 一句话：**预设绑定一个云端源，双方各自维护 manifest，比对 manifest 就知道谁缺什么，只传/只下变化的部分。**

---

## 0. 名词

| 词 | 含义 |
|---|---|
| 预设 | 一组枪包的集合，本地一个目录 |
| 源 | 预设绑定的云端位置（蓝奏分享链接 + 密码） |
| manifest | 一份 JSON 清单（文件名为 `.cfg` 以通过网盘白名单；兼容旧 `.txt`），描述预设里有哪些文件（路径 / 大小 / sha256 / 类型） |
| 本地 manifest | 程序扫描本地预设目录算出来的 manifest |
| 云端 manifest | 开发者发布时自动生成并上传的 manifest |
| 身份 | 全局角色：玩家 / 开发者 |

---

## 1. 范围

**做**

- 预设绑定云端源，一键检查更新、增量同步
- 开发者认证后一键发布（只传差异），自动产出分享链接和密码
- 两套界面（玩家 / 开发者），全局身份切换
- 打包/解包、校验、错误处理、进度反馈

**不做**

- 不做服务端、不做账号体系（只有蓝奏账号）
- **不做玩家端回滚**（已确认不需要）
- 不做静默自动更新（所有传输都要人确认）
- 不接管游戏启动

---

## 2. 角色与身份

**身份是全局的**，不是每个预设各一个。

| 身份 | 解锁条件 | 能力 |
|---|---|---|
| 玩家 | 默认 | 绑定源、检查更新、同步、删除本地多余（询问后） |
| 开发者 | 填蓝奏账号 + 密码并登录成功 | 上传、发布、删除云端多余、查看发布记录 |

- 认证信息存本机配置，带「退出认证」
- 未认证点「切换为开发者」→ 弹认证框，失败给明确原因（账号未激活 / 密码错 / 网络）
- 切换是界面级的，不改数据；切回玩家后开发者入口隐藏、配置保留

## 3. 数据模型

### 3.1 manifest

云端 manifest 的文件名是 `_pulses_manifest.cfg`，**内容仍然是 JSON**。
蓝奏不接受 `.json` / `.toml` / `.yaml`，`.cfg` 可以上传；所以只改后缀，
解析仍走标准库 `json`（C 实现，快且只有一套结构）。旧版
`_pulses_manifest.txt`（JSON）仍然兼容读取，发布后自动迁移。

```json
{
  "format": "pulses-manifest",
  "schema": 2,
  "name": "SSR预设包",
  "version": "2026.10.18",
  "generation": 7,
  "min_app": "2.5.0",
  "generated_at": "2026-10-18T01:00:00Z",
  "notes": "新增 3 把枪，修贴图",
  "manifest_sha256": "…",
  "files": [
    {"path": "gun_alpha.zip", "type": "zip", "size": 41943040,
     "sha256": "9f2c…", "packed_size": 41943040,
     "packed_sha256": "9f2c…"},
    {"path": "gun_beta.zip", "type": "folder", "target": "gun_beta",
     "size": 52428800, "files": 42, "sha256": "7d1a…",
     "packed_size": 39800000, "packed_sha256": "…"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `format` | 固定 `pulses-manifest`，防止误读别的 JSON |
| `schema` | 当前 2；高于程序支持版本时提示升级 |
| `manifest_sha256` | 整份 manifest（不含本字段）的规范化摘要，读入时校验 |
| `version` | 展示用版本号（默认日期式） |
| `generation` | 每次发布自增；客户端结束时校验，防止装出半新半旧 |
| `min_app` | 低于此版本的程序提示先升级 |
| `files[].path` | 上传到网盘的文件名，**也是比对唯一键**（不区分大小写） |
| `files[].type` | `zip` 原样 / `folder` 需解压 / `file` 其他 |
| `files[].target` | 仅 `folder` 用：解压到哪个目录 |
| `files[].sha256` | 内容摘要（`folder` 为树摘要，见 4.6），唯一可信标识 |
| `files[].size` | 逻辑体积；`folder` 为解压后总字节 |
| `files[].packed_size` | 实际传输体积；`folder` 为打包后 zip 大小 |
| `files[].packed_sha256` | 传输包摘要；下载后先验包，再解压/落盘 |
| `files[].files` | 仅 `folder`：文件个数（展示与自检用） |

> `manifest_sha256` 是完整性校验，不是数字签名；能发现损坏/误改，不能阻止
> 有意的重新计算。真正的防篡改需要服务端签名/私钥，蓝奏分享模式做不到。

**哪些东西不进 manifest**

`index.json` / `version.txt` / `description.txt` 是程序自己维护的预设元数据，
`tacz-pre.toml` / `blacklist.txt` / `tacz_default_gun`（兼容 `tacz-default-gun`）属于 TACZ 而不是预设。
它们都在扫描时被排除——如果云端 manifest 里出现，`check()` 会过滤掉并记一条警告，
否则会变成"云端有、本地永远没有"的死循环。

### 3.2 本地状态目录

```
PulsesSwap_database/online/
├── sources.json               每个预设绑定的源（URL / 密码 / 上次版本）
├── cloud/<preset>.json        上次拉到的云端 manifest（离线可用 + 变更对比）
├── local/<preset>.json        上次算出的本地 manifest（展示用缓存）
├── cache/<root-hash>.json     哈希缓存，按内容目录区分（预设目录 / TACZ 目录）
└── staging/<preset>/          下载暂存 + journal.json（安装日志）
```

**不做玩家回滚**，所以没有 backup 目录。

### 3.3 源配置

```json
{"preset": "SSR预设包",
 "lanzou": {"url": "https://xxx.lanzoul.com/bXXXX", "password": "28pm"},
 "cloud_path": "/PulsesSwap/SSR预设包",
 "auto_check": true}
```

- 玩家只填 `lanzou`；开发者只填 `cloud_path`（账号是全局认证的）
- `auto_check` 默认开启：启动时后台检查，有更新在预设卡片显示角标

## 4. 差异引擎

### 4.1 两方比对（最终定稿）

只比 **本地 manifest** 和 **云端 manifest**，不做三方比对。

| 本地 | 云端 | 玩家 | 开发者 |
|---|---|---|---|
| 无 | 有 | **补齐**：下载 | **删除**：从云端移除 |
| 有 | 有，哈希相同 | 跳过 | 跳过 |
| 有 | 有，哈希不同 | **更新**：下载覆盖 | **更新**：上传覆盖 |
| 有 | 无 | **询问是否删除**（默认保留） | **必须上传**（可单项取消） |
| 本地损坏 | 有 | **重下** | 不适用（开发者本地永远最新） |

### 4.2 动作词表

`download / upload / skip / delete_cloud / delete_local / ask_delete_local / repair / blocked`

### 4.3 打包与类型

统一用 `.zip`（蓝奏不接受奇怪扩展名）。文件夹型枪包上传前打包，**类型写在 manifest 里**：

| type | 上传时 | 下载后 |
|---|---|---|
| `zip` | 原样 | 原样放入 |
| `folder` | 打包成 `X.zip`（确定性：条目排序、时间戳归零、压缩级固定） | 解压到 `target` |
| `file` | 原样 | 原样 |

同名冲突（预设里同时有 `X/` 和 `X.zip`）→ 文件夹打包成 `X.folder.zip`，`target` 仍是 `X`。

### 4.4 边界规则

| 规则 | 处理 |
|---|---|
| 云端有、manifest 没列的文件 | 视为**未托管**（如 description.txt），完全忽略 |
| 路径大小写 | 比较时不敏感，显示保留原样 |
| 非法文件名 / 超长 | 标红，不进入传输 |
| 单文件 > 100MB | 标红「超过网盘上限」，建议分卷 |
| 磁盘空间不足 | 下载前整体预检查，直接拒绝开始 |
| 忽略文件 | `.DS_Store` / `Thumbs.db` / `*.tmp` / 隐藏文件 |

### 4.5 输出结构

```python
Plan(role="player", items=[DiffItem(path, action, local_sha, cloud_sha,
                                    size, reason)], totals={...}, blocked=[...])
```

### 4.6 树摘要（folder 类型的 sha256）

文件夹型枪包在云端是一个 zip，但本地是一个目录。要比对"变了没有"，
不能拿 zip 的哈希去比目录，也不能每次都打包一遍（2GB 要几十秒）。

做法是给目录算一个**树摘要**：

```
h = sha256("pulses-tree-v1\n")
for (rel, size, file_sha) in sorted(树里每个文件):
    h.update(rel + "\0" + size + "\0" + file_sha + "\n")
```

它只取决于内容，与打包细节无关，因此：

- 开发者本地算一次 = 上传前算一次，不会因为打包参数变了就"全变了"
- 玩家解压后再算一次，能验证下载是否完整（比校验 zip 字节更有意义）
- 打包用同一份文件清单（`iter_tree`），保证"打包 → 解包 → 再算"一定对得上

每个文件的 sha256 走 `(路径, size, mtime)` 缓存，所以第二次扫描只做 stat。

## 5. 玩家流程

```
① 预设齿轮 → 填分享链接 + 密码 → [测试连接]
      成功：显示云端版本 / 文件数 / 总体积
② [检查更新] → 下载云端 manifest（几十 KB）→ 与本地 manifest 比对
      2GB 预设也 <1 秒（不列云端文件、不算云端哈希）
③ 差异确认框
      新增 2 · 更新 1 · 本地多余 0 · 一致 21 · 合计下载 142 MB
      逐项可勾选；本地多余项单独列出并询问「是否删除」（默认保留）
④ 开始同步
      列一次云端文件（拿 file_id）→ 逐个下载 → 逐包校验 sha256
      进度：当前文件 + 总进度 + 速度 + 预计剩余
⑤ 安装
      下载到 staging → 校验 → 解压/放入 → 原子替换正式目录
⑥ 完成
      更新本地 manifest 与云端 manifest 存档；提示「已同步到 v2026.10.18」
```

**失败处理**

| 失败点 | 处理 |
|---|---|
| 拉 manifest 失败 | 用上次的云端 manifest，界面标「离线」 |
| 分享密码错 | 明确提示，引导去齿轮里改 |
| 某个文件下载失败 | 换域名重试 3 次；仍失败则该包标记失败，其余继续 |
| 校验不符 | 重下一次；仍不符标记失败并提示 |
| 中途关程序 | staging 残留，下次启动清理；正式目录未受影响 |

## 6. 开发者流程

```
① 切换身份 → 认证（蓝奏账号 + 密码）→ 登录成功才解锁
② 预设齿轮 → 填云端路径（如 /PulsesSwap/SSR预设包）
③ [扫描差异]
      本地 manifest（现算）vs 云端 manifest
      新增 2 · 更新 1 · 一致 21 · 云端多余 0
④ 确认发布框
      版本号（默认日期）+ 更新说明
      逐项勾选（新增/更新默认全选，可取消）
      云端多余项：询问「删除云端」还是「保留」
      [预演] 只显示将做什么，不传输
⑤ 开始发布
      逐级确保文件夹存在（有就复用，不重复建）
      逐个上传（文件夹型先打包）
      进度同玩家侧
⑥ 替换 manifest
      所有文件上传成功后，最后上传 manifest（generation +1）
      失败则线上仍是完整旧版
⑦ 完成
      显示版本、文件数、体积
      自动取分享链接 + 密码 → 一键复制
```

## 9. 启动行为

1. 窗口先出来（不等扫描）
2. 后台线程扫描所有预设目录，**增量重算**本地 manifest：
   - 只取 `(路径, size, mtime)`，三者未变就沿用旧哈希
   - 2GB 预设无改动约 200ms
3. 扫描完刷新卡片状态
4. 若 `auto_check` 开启且身份为玩家 → 后台拉云端 manifest 比对，有更新给卡片加角标

| 场景 | 提示与处理 |

## 12. 两个已定稿的决策

**1. 玩家改过的同名文件 → 接受覆盖（方案 A）**

两方比对下，玩家手动改过的枪包（同名、哈希不同）会被判定为「更新」并被云端覆盖，
不做备份、不做回滚。界面在同步确认框里会写清楚"将覆盖本地修改"。

**2. 删除本地多余枪包 → 走系统回收站**

Windows 用 `SHFileOperationW`（`FOF_ALLOWUNDO`），Linux/macOS 走 freedesktop
回收站规范；都不支持时才硬删。删错了能从回收站找回来。

**对原方案的三处修正**

1. `folder` 类型的 `sha256` 改为**树摘要**，另加 `packed_size` 表示传输体积（见 4.6）。
2. 蓝奏下载链路现在是**两段式**：`apifile` 给出的地址是下载页，

## 14. 界面设计（第二轮）

### 视觉体系

方向：**贴近 iOS 的分组列表**——灰底、白卡、无描边、少装饰，一眼看懂下一步做什么。

| 层级 | 用色 | 用途 |
|---|---|---|
| 0 底 | `#F2F3F5` | 窗口背景（中性浅灰） |
| 1 面 | `#FFFFFF`，**无描边** | 分组卡片 |
| 2 填充 | `#F4F6F7` | 输入框、列表框、拖入框 |

- 圆角：卡片 14 / 控件 10 / 进度条 4
- 分组列表：卡片内逐行排布，行底一条内缩 1px 分隔线（`#E9EDEF`），选中态是强调软色圆角块
- 按钮只有两种：**主操作**＝实心强调色；**其余**＝强调色文字（tinted），都没有边框
- 表头是一行小号灰字，不加徽章/竖条/渐隐线
- 低频操作收进菜单：卡头是「更多」文字按钮，卡片行内才用「⋯」
  （两处长得一样会让用户不知道点哪一个）
- 主界面同时露出的按钮不超过 6 个
- 空列表一定给空状态（圆环 + 标题 + 提示），不留空灰底
- 状态行是唯一需要用户行动的信息：13px，可行动时加粗，且不排在信息末尾
- 输入框的附带动作（如版本号的「保存」）做成框内尾随文字按钮，不另起平级按钮
- 间距：卡片内 16×12，块之间 10，紧邻 6，极小 4
- 字号（像素）：展示 22 / 标题 18 / 小标题 16（粗）/ 正文 14 / 次要 13 / 极小 12
  - 侧边栏导航用 16（比正文大一档，主入口要压得住）
  - 原生 Tk 控件（Listbox / Canvas 文字）统一走 `tk_font()` 的负数字号，和 CTk 同一套缩放

### 结构

- **段落标题**：`数字徽章 + 标题 + 渐隐细线`，三块内容共用同一骨架
- **预设行**：状态点（有更新时呼吸）+ 名称 + 版本/枪包数/体积 + 状态行 + 动作
- **详情条**：横条放在右列顶部（名称 / 状态 / 版本可改 / 云端来源），不再占左列纵向空间
- **弹窗**：标题（主文字色）+ 24×2 强调短线 + 副标题 + 内容 + 分割线 + 按钮条
- **空状态**：极简圆环 + 标题 + 提示，居中

### 表单

- 字段结构统一为「标签 + 输入框 + 提示行」，提示行**始终占位**，报错不顶动布局
- 输入框：聚焦描边弹到强调色；校验失败描边转红、提示行变红，重新输入即恢复
- 密码框带「显示 / 隐藏」，放提示行右端（不占用输入框宽度）
- 所有输入框带右键菜单：剪切 / 复制 / 粘贴 / 全选 / 清空
- 提交中：按钮变「正在…」并禁用，字段一起禁用；失败留在原弹窗、保住已填内容
- 可选/高级项（如备用链接）默认收起，需要时再展开

### 动效

| 场景 | 曲线 | 时长 |
|---|---|---|
| 弹窗入场 | 阻尼弹簧（过冲 ~7%） | 280ms |
| 按钮按下 / 松开 | 快沉 / 轻回弹 | 70 / 200ms |
| 侧边栏滑块 | 弹簧（过冲 ~5%） | 240ms |
| 最近面板展开 | 高度弹簧 | 240ms |
| 卡片选中 / 勾选 | 轻弹簧（过冲 ~3%） | 170–210ms |
| 输入框聚焦 / 填入 | 描边弹到强调色 + 呼吸一次 | 200 / 400ms |
| 有更新的状态点 | 呼吸（明暗往复） | 1400ms 循环 |

### DPI

CTk 控件自身会按 `widget_scaling` 放大，尺寸**不能**再乘 `px()`，
否则 125% 下卡片会高出 20px。规则：

- CTk 控件尺寸 → 原始令牌（`H_CARD`、`R_CONTROL`…）
- `tk.Canvas` 尺寸、`grid minsize`、`place` 偏移 → `px()`
- 用 `grid` 布局的卡片要 `grid_propagate(False)`，只写 `pack_propagate` 无效
