# Swap-Online 设计与实施计划

> 分支：`feature/online`
> 目标：把「预设的更新与发布」从手动文件操作，变成**绑定一个云端源就能自动比对、只传/只下变化部分**的在线流程。

---

## 一、目标与边界

**要解决的**

| 现在 | Swap-Online 之后 |
|---|---|
| 玩家拿到的预设是死的，更新要人手动发 zip、手动导入 | 预设绑定一个蓝奏分享，点一下「检查更新 → 同步」 |
| 开发者每次要打包、导出、传网盘、发链接 | 填一次账号和路径，之后点「发布」，自动算出差异并只传变化的枪包 |
| 2GB 整包传输 | **取所需**：改一把枪只传 30–60MB |
| 导出预设包 / 导出增量更新 两个按钮 | 移除（被线上流程取代），仅保留本地导入兜底 |

**不做**

- 不做账号体系、不做服务端（零服务器）
- 不做自动静默更新（所有上传/下载都要人确认）
- 不接管游戏启动

## 二、数据模型

### 2.1 manifest.json（云端，唯一入口）

```json
{
  "schema": 1,
  "name": "SSR预设包",
  "version": "2026.10.18",
  "min_app": "2.5.0",
  "generated_at": "2026-10-18T01:00:00Z",
  "notes": "新增 3 把枪，修贴图",
  "files": [
    {"name": "gun_alpha.zip", "size": 41943040,
     "sha256": "9f2c…", "mtime": "2026-10-17T12:00:00Z"},
    {"name": "gun_beta.zip",  "size": 52428800,
     "sha256": "7d1a…", "mtime": "2026-10-15T08:30:00Z"}
  ]
}
```

设计要点：
- **只按文件名对齐**（网盘里换文件 id 会变，名字不变）
- `sha256` 是唯一可信标识；`size` 用于预检查；`mtime` 仅作提示
- `schema` 只增字段不改语义，老客户端永远读得懂
- `min_app` 低于当前版本时明确提示「请先升级软件」

### 2.2 本地状态（`PulsesSwap_database/online/`）

```
online/
├── sources.json          ← 每个预设绑定的源（URL / 密码 / 上次同步版本）
├── manifests/<preset>.json   ← 上次成功同步的 manifest（离线可用）
├── staging/<preset>/     ← 下载暂存（安装成功才动正式目录）
└── backup/<preset>/<version>/ ← 保留上一版，支持一键回滚
```

`state.json` 里记录每个预设：当前版本、每文件的 sha256、上次同步时间、上次错误。

### 2.3 源绑定（一个预设可以有多个源）

```json
{"preset": "SSR预设包",
 "sources": [
   {"type": "lanzou", "url": "https://xxx.lanzoul.com/bXXXX",
    "password": "28pm", "priority": 1}
 ],
 "auto_check": true}
```

`priority` 让客户端在某个源失败时自动降级到下一个。

## 三、核心引擎（两端共用）

### 3.1 差异引擎 `diff(local, remote) → plan`

| 情况 | 判定 | 处理 |
|---|---|---|
| 本地没有、云端有 | **新增** | 下载 |
| 两边都有、sha256 相同 | **一致** | 跳过（这就是「取所需」） |
| 两边都有、sha256 不同 | **更新** | 下载覆盖 |
| 本地有、云端没有 | **已移除** | 询问：保留 / 删除（默认保留，标记为「本地独有」） |
| 本地文件损坏（哈希不符） | **损坏** | 建议「修复」= 重新下载 |

### 3.2 哈希缓存

对每个本地文件缓存 `(size, mtime) → sha256`，避免每次全量重算 2GB。
`mtime` 变了才重算。

### 3.3 下载器

- 单文件串行（避免打满带宽），可配置并发 1–4
- 断点续传：蓝奏不支持 Range → 失败整包重来，但**换域名重试 3 次**
- 每包校验 sha256，不符重下一次
- 进度回调：`(当前文件, 已下载, 总大小, 已完成数, 总数)`
- 安装：暂存 → 校验 → 原子替换 → 保留旧版

### 3.4 上传器（开发者侧）

- 登录（账号 + 密码，本地保存）
- `ensure_folder(path)`：按路径逐级找/建文件夹（**已存在的复用，不重复建**）
- 只传差异：新增 + 更新；删除可选
- 上传前先传 manifest 的临时副本，全部成功后再替换正式 manifest（**保证线上永远是一个完整版本**）
- 完成后 `task=18` 取分享链接 + 密码，一键复制

## 四、功能全景

### 4.1 玩家侧（12 项）

| # | 功能 | 说明 |
|---|---|---|
| P1 | 绑定源 | 在预设里填蓝奏 URL + 密码，校验通过后保存 |
| P2 | 检查更新 | 拉 manifest → 比对 → 显示「已是最新 / N 个更新 / 共 X MB」 |
| P3 | 选择性同步 | 差异列表逐项勾选，默认全选「新增+更新」 |
| P4 | 增量下载 | 只下差异文件，逐个校验 |
| P5 | 断点/重试 | 失败自动换域名重试，失败项单独重试 |
| P6 | 安装与回滚 | 原子替换；保留上一版；一键回滚 |
| P7 | 自动检查 | 启动时后台检查（可关），有更新时预设卡片显示角标 |
| P8 | 离线可用 | 无网时用本地缓存 manifest，界面标「离线」 |
| P9 | 完整性校验 | 一键校验本地所有文件，列出损坏项并可「修复」 |
| P10 | 变更说明 | 显示版本号、发布时间、notes、文件级差异 |
| P11 | 多源降级 | 主源失败自动试备用源 |
| P12 | 本地导入兜底 | 保留拖入 zip 的手动导入（线上不可用时的退路） |

### 4.2 开发者侧（10 项）

| # | 功能 | 说明 |
|---|---|---|
| D1 | 账号绑定 | 账号 + 密码，登录后保存 cookie |
| D2 | 路径绑定 | 预设 → 云端路径（如 `/PulsesSwap/SSR预设包`），自动逐级创建 |
| D3 | 扫描比对 | 本地预设 vs 云端文件夹，列出新增/更新/移除/一致 |
| D4 | 选择性上传 | 逐项勾选，默认「新增+更新」 |
| D5 | 只传差异 | 取所需，避免重复上传 2GB |
| D6 | 版本与说明 | 版本号（默认日期）、更新说明，写入 manifest |
| D7 | 安全发布 | 先传文件 → 再替换 manifest，失败不留半成品 |
| D8 | 分享输出 | 自动取分享链接 + 密码，一键复制 |
| D9 | 发布历史 | 记录每次发布的版本、时间、文件数、体积 |
| D10 | 预演模式 | dry-run：只显示将要做什么，不实际传输 |

### 4.3 通用（8 项）

| # | 功能 | 说明 |
|---|---|---|
| C1 | 统一进度组件 | 单文件进度 + 总进度 + 速度 + 剩余时间 |
| C2 | 统一错误面板 | 错误分类（网络/密码/结构/磁盘），带「重试」「复制详情」 |
| C3 | 限速与并发 | 并发 1–4，可选限速（默认不限） |
| C4 | 磁盘预检查 | 下载前按总大小检查剩余空间 |
| C5 | 诊断工具 | 「测试分享解析」：输入 URL+密码，显示解析到的文件列表 |
| C6 | 日志 | 线上操作写入现有日志系统（完整日志模式可见细节） |
| C7 | 设置项 | 自动检查、并发数、保留版本数、蓝奏账号 |
| C8 | 应用自更新 | 同一套机制可用于更新软件本体（后续里程碑） |

## 五、UI 改造

### 5.1 预设列表：从「窄条」变成卡片

现在：`Listbox` 一行一个名字，信息量几乎为零。

改成**卡片列表**（垂直滚动），每张卡片：

```
┌─────────────────────────────────────────────┐
│ ● SSR预设包                       [已应用]   │
│   v2026.10.18 · 24 个枪包 · 1.8 GB           │
│   ⟳ 有 3 个更新（共 142 MB）      [更新] [⋯] │
└─────────────────────────────────────────────┘
```

- 左侧状态点：绿色=已应用且最新，橙色=有更新，灰色=未应用，红色=源失效
- 右侧按钮随状态变化：`更新` / `已最新` / `绑定源` / `重试`
- `⋯` 打开详情

### 5.2 预设详情：右侧抽屉 / 面板

三个标签页：

| 标签 | 内容 |
|---|---|
| **概览** | 版本、来源、上次同步、总大小、状态、[更新][回滚][校验] |
| **枪包** | 卡片化的枪包列表：名字、大小、状态（一致/待更新/本地独有/损坏） |
| **来源** | 绑定的蓝奏链接 + 密码（打码显示）、[测试连接][更换源]、发布记录 |

### 5.3 同步对话框


## 六、技术架构

```
src/online/
├── __init__.py
├── manifest.py            manifest 读写 / 校验 / 规范化
├── hashing.py             sha256 + (size, mtime) 缓存
├── provider_base.py       抽象：list / download / upload / share
├── provider_lanzou.py     匿名下载（已完成并验证）
├── provider_lanzou_account.py  登录 / 文件夹 / 上传（已完成骨架）
├── diff.py                差异计算 → plan
├── downloader.py          下载 + 重试 + 校验 + 进度
├── uploader.py            上传 + 安全发布 + 分享
├── updater.py             安装 / 回滚 / 校验
└── service.py             对外门面：scan / sync / publish

src/ui/online_*.py         卡片、详情、同步框、发布框
tools/publish.py           命令行发布（CI/手动兜底）
```

**依赖**：仍然只用标准库（`urllib` / `hashlib` / `json` / `mimetypes`）。

## 七、分阶段实施

### M1 · 引擎（不碰 UI）
- `manifest.py` / `hashing.py` / `diff.py` / `downloader.py` / `updater.py`
- 用本地目录模拟云端，跑通「比对 → 下载 → 校验 → 安装 → 回滚」
- 验收：脚本能对真实蓝奏分享完成一次完整同步

### M2 · 发布端
- `uploader.py` + `service.publish`
- 验收：真实账号上传一个 40MB 文件 → 拿到分享链接 → 用 M1 的客户端同步回来

### M3 · UI 改造
- 预设卡片化 + 详情面板
- 同步对话框 + 发布对话框
- 移除「导出预设包 / 导出增量更新」
- 验收：全流程只靠点击完成

### M4 · 打磨
- 自动检查、角标、回滚、校验、诊断、发布历史
- 应用自更新
- 验收：断网、密码错、源失效、磁盘满等异常都有明确提示

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 蓝奏接口变更 | provider 隔离；域名池；失败降级到手动导入 |
| 免费额度/限速 | 单文件 100MB 上限（枪包 30–60MB 安全）；分批上传 |
| 大文件传输中断 | 重试 3 次 + 换域名；不支持 Range 就整包重下 |
| 上传中断留下半成品 | manifest 最后替换；失败不动正式文件 |
| 账号密码安全 | 只存本机；只在登录蓝奏时使用 |
| 云端被误改 | 每次同步前校验 manifest 结构；保留上一版可回滚 |
| 预设被本地改动 | 差异面板里明确标「本地独有」，默认不删除 |

## 九、需要你确认的决策点

1. **版本号格式**：日期式（`2026.10.18`）还是语义化（`1.4.0`）？我倾向日期式，发布简单。
2. **云端路径**：默认 `/PulsesSwap/<预设名>` 可以吗？
3. **移除的枪包**：默认「保留本地、标记为本地独有」，还是直接删？
4. **自动检查更新**：默认开启还是关闭？
5. **保留几个旧版本**：默认 1 个（占双倍空间）。
6. **导出按钮**：确认直接移除「导出预设包 / 导出增量更新」，只保留本地导入兜底？
