# Swap-Online 设计与实施计划

> 分支：`feature/online`
> 目标：把「预设的更新与发布」从手动文件操作，变成**绑定一个云端源就能自动比对、只传/只下变化部分**的在线流程。

---

## 一、目标与边界

**要解决的**

| 现在 | Swap-Online 之后 |
|---|---|
| 玩家拿到的预设是死的，更新要人手动发 zip、手动导入 | 预设绑定一个蓝奏分享，点一下「检查更新 → 同步」 |
| 开发者每次要打包、导出、传网盘、发链接 | 填一次账号和路径，之后点「发布」，自动算出差异并只传变化的枪包 |
| 2GB 整包传输 | **取所需**：改一把枪只传 30–60MB |
| 导出预设包 / 导出增量更新 两个按钮 | 移除（被线上流程取代），仅保留本地导入兜底 |

**不做**

- 不做账号体系、不做服务端（零服务器）
- 不做自动静默更新（所有上传/下载都要人确认）
- 不接管游戏启动

## 二、数据模型

### 2.1 manifest.json（云端，唯一入口）

```json
{
  "schema": 1,
  "name": "SSR预设包",
  "version": "2026.10.18",
  "min_app": "2.5.0",
  "generated_at": "2026-10-18T01:00:00Z",
  "notes": "新增 3 把枪，修贴图",
  "files": [
    {"name": "gun_alpha.zip", "size": 41943040,
     "sha256": "9f2c…", "mtime": "2026-10-17T12:00:00Z"},
    {"name": "gun_beta.zip",  "size": 52428800,
     "sha256": "7d1a…", "mtime": "2026-10-15T08:30:00Z"}
  ]
}
```

设计要点：
- **只按文件名对齐**（网盘里换文件 id 会变，名字不变）
- `sha256` 是唯一可信标识；`size` 用于预检查；`mtime` 仅作提示
- `schema` 只增字段不改语义，老客户端永远读得懂
- `min_app` 低于当前版本时明确提示「请先升级软件」

### 2.2 本地状态（`PulsesSwap_database/online/`）

```
online/
├── sources.json          ← 每个预设绑定的源（URL / 密码 / 上次同步版本）
├── manifests/<preset>.json   ← 上次成功同步的 manifest（离线可用）
├── staging/<preset>/     ← 下载暂存（安装成功才动正式目录）
└── backup/<preset>/<version>/ ← 保留上一版，支持一键回滚
```

`state.json` 里记录每个预设：当前版本、每文件的 sha256、上次同步时间、上次错误。

### 2.3 源绑定（一个预设可以有多个源）

```json
{"preset": "SSR预设包",
 "sources": [
   {"type": "lanzou", "url": "https://xxx.lanzoul.com/bXXXX",
    "password": "28pm", "priority": 1}
 ],
 "auto_check": true}
```

`priority` 让客户端在某个源失败时自动降级到下一个。

## 三、核心引擎（两端共用）

### 3.1 差异引擎（按角色 + 三方比对）

#### 3.1.1 为什么必须按角色分开

同一件事在两端含义**相反**：

| 本地 | 云端 | 玩家（拉：云端为准） | 开发者（推：本地为准） |
|---|---|---|---|
| 无 | 有 | **新增** → 下载 | **云端多余** → 建议删除（需确认） |
| 有 | 有，哈希相同 | 一致 → 跳过 | 一致 → 跳过 |
| 有 | 有，哈希不同 | **更新** → 下载覆盖 | **更新** → 上传覆盖 |
| 有 | 无 | **本地独有** → 忽略（玩家自己加的，绝不动） | **新增** → 上传 |
| 有，但已损坏 | 有 | **损坏** → 修复（重下） | **本地损坏** → 禁止上传，先修 |

开发者的本地永远是最新版，所以「本地有云端无」对他就是**待推送**；
玩家则可能自己塞了枪包，所以「本地有云端无」对他就是**不许碰**。

#### 3.1.2 两方比对（最终定稿）

只比 **本地 manifest** 和 **云端 manifest**，不做三方比对。

| 本地 | 云端 | 玩家 | 开发者 |
|---|---|---|---|
| 无 | 有 | **补齐**：下载 | **删除**：从云端移除 |
| 有 | 有，哈希相同 | 跳过 | 跳过 |
| 有 | 有，哈希不同 | **更新**：下载覆盖 | **更新**：上传覆盖 |
| 有 | 无 | **询问是否删除**（默认保留 —— 多出来的不影响使用） | **必须上传**（每项可单独取消） |
| 本地文件损坏 | 有 | **重下** | 不适用（开发者本地永远最新） |

开发者侧「本地有云端无」= 新增内容，默认全选上传，但每项带取消勾选；
玩家侧同一情况只提示、不擅自删。

### 3.1.3 路径与命名

- **以相对路径为键**（`gunpacks/alpha.zip`），不是单纯文件名 —— 预设允许子目录，云端也支持嵌套文件夹（你那个分享里 `MC/C4Pro` 就是嵌套的）
- 比较时**大小写不敏感**（网盘基本如此），显示保留原始大小写
- 上传前做**文件名合法性检查**（非法字符、超长、保留名），不合法直接标红，不让传
- 云端有、manifest 里没有的文件 → 归为**未托管文件**（比如你分享里的 `description.txt`、`C4-PRO.jar`），引擎**完全忽略**，不参与比对、不会被删

#### 3.1.4 文件夹形态的枪包

预设里的枪包可能是**解压后的文件夹**，而网盘只能传文件。所以：

- 上传前把文件夹**确定性打包成 zip**（条目排序、时间戳归零、压缩级别固定）
- 确定性打包保证同一份内容每次得到**同一个 sha256**，否则每次发布都会被判定成「变了」
- 玩家下载后按需解压，或保持 zip（由预设的存储模式决定）

#### 3.1.5 重命名识别

本地改了名 → 表现为「本地新增 X + 云端多余 Y」。若 `hash(X) == hash(Y)`，判定为**疑似重命名**：

- 网盘支持重命名就调重命名接口（省一次传输）
- 不支持就退化成「删 Y + 传 X」，并在界面上说明原因

#### 3.1.6 阻塞项（不进入传输）

| 阻塞原因 | 表现 |
|---|---|
| 单文件 > 100MB | 标红「超过网盘单文件上限」，建议分卷 |
| 文件名非法 | 标红，提示改名 |
| 本地文件读不出来 | 标红「无法读取」 |
| 磁盘空间不足 | 下载前整体预检查，直接拒绝开始 |
| `min_app` 高于当前版本 | 提示先升级软件 |

#### 3.1.7 原子性与并发

- manifest 带 `generation` 自增号；客户端**开始时取一次**，全部文件下完后校验 generation 是否变化
- 若变化（开发者刚好发了新版）→ 提示「云端已更新，请重新检查」，不会装出半新半旧的版本
- 开发者发布：先传所有文件 → 最后替换 manifest → 失败时线上仍是完整旧版
- 每个文件下完立即校验 sha256，不符则重下一次，两次不符则标记失败并跳过

#### 3.1.8 输出的计划结构

```python
Plan(
  role="player" | "developer",
  first_sync=False,
  items=[
    DiffItem(path="gunpacks/alpha.zip", action="download",
             local_sha=None, cloud_sha="9f2c…", base_sha=None,
             size=41943040, reason="新增"),
    DiffItem(path="gunpacks/beta.zip", action="conflict",
             local_sha="aa…", cloud_sha="bb…", base_sha="cc…",
             size=52428800, reason="本地与云端都改过"),
    ...
  ],
  totals={"download": 3, "upload": 0, "skip": 21,
          "bytes_down": 142000000, "bytes_up": 0},
  blocked=[...],
)
```

动作词表：`download / upload / skip / delete_cloud / keep_local /
repair / conflict / blocked / rename`。

### 3.1.9 manifest 对 manifest（这是整个方案能"几乎不花时间"的关键）

两端都维护 manifest，**同步时只比 manifest，不去列云端文件**：

```
玩家端                                    云端
  ├─ 本地 manifest（自己算，按需重算）      ├─ manifest.json（开发者发布时自动生成并上传）
  ├─ base manifest（上次同步下载的那份）    │
  └─ 拉云端 manifest ←─────────────────────┘
            ↓
      三份 manifest 直接比对（纯内存，毫秒级）
```

- **本地 manifest**：扫描预设目录得到（文件名 / 大小 / sha256），带 `(size, mtime)` 缓存，只有变化的文件才重算哈希
- **云端 manifest**：一个几十 KB 的 JSON，下载一次即可
- **base manifest**：上一次成功同步时下载的云端 manifest，存本地存档 —— 它就是三方比对的第三方，**零额外成本**

于是「检查更新」= 下载 1 个 JSON + 内存里比三份表 → **不到 1 秒**，哪怕预设是 2GB。

> 唯一需要列云端文件列表的场景：首次绑定源（拿到 file_id）和实际下载/上传时
> （蓝奏的 file_id 会随文件替换而变，manifest 里不能存 id，只能存相对路径）。

### 3.1.10 身份切换与认证

```
┌─ 侧边栏底部 / 顶部 ────────────────────┐
│  当前身份：玩家            [切换身份 ▾] │
└────────────────────────────────────────┘
```

| 身份 | 解锁条件 | 能做什么 |
|---|---|---|
| **玩家** | 默认 | 绑定源、检查更新、同步、回滚 |
| **开发者** | 必须先「认证」：填蓝奏账号 + 密码并登录成功 | 上传、发布、删除云端、查看发布历史 |

- 认证信息只存本机（`settings.json` 里加密或至少不明文打印），带「退出认证」
- 未认证时点「切换为开发者」→ 弹认证框；认证失败（账号未激活/密码错）给出明确原因
- 身份切换是**界面级**的，不改数据；切换回玩家后开发者入口隐藏但配置保留

### 3.1.11 每个预设一个「连接设置」

像在 agent 里填 key 一样，预设卡片上有个齿轮：

**玩家身份** → 填 **分享链接 + 密码**

```
┌ 预设「SSR预设包」· 连接设置 ────────────────┐
│ 分享链接  [https://xxx.lanzoul.com/bXXXX ] │
│ 提取密码  [28pm                          ] │
│                    [测试连接]  [保存]      │
└────────────────────────────────────────────┘
测试连接 → 显示：云端 v2026.10.18 · 24 个文件 · 1.8 GB
```

**开发者身份** → 填 **云盘文件夹路径**（账号是全局认证的）

```
┌ 预设「SSR预设包」· 发布设置 ────────────────┐
│ 云端路径  [/PulsesSwap/SSR预设包         ] │
│ 账号      nimshade（已认证）               │
│                    [扫描差异]  [保存]      │
└────────────────────────────────────────────┘
扫描差异 → 列出新增/更新/一致/云端多余，确认后发布
```

### 3.2 哈希缓存

对每个本地文件缓存 `(size, mtime) → sha256`，避免每次全量重算 2GB。
`mtime` 变了才重算。

### 3.2.1 启动时的快速重算

每次启动都重算本地 manifest，但要"快"：

1. 先读 `online/manifests/local-<preset>.json`（上次结果）
2. 遍历预设目录，对每个文件只取 `(相对路径, size, mtime)`
3. **三者都没变的文件直接沿用旧 sha256**，只有变了的才真正读文件算哈希
4. 大文件（>8MB）用分块读 + 可中断，避免启动卡顿
5. 整个扫描放到后台线程，算完再更新界面（不阻塞窗口显示）
6. 结果写回缓存

2GB 预设、无改动时：约 200ms（纯 stat）；有 1 个 40MB 枪包变动：多约 150ms。

### 3.3 下载器

- 单文件串行（避免打满带宽），可配置并发 1–4
- 断点续传：蓝奏不支持 Range → 失败整包重来，但**换域名重试 3 次**
- 每包校验 sha256，不符重下一次
- 进度回调：`(当前文件, 已下载, 总大小, 已完成数, 总数)`
- 安装：暂存 → 校验 → 原子替换 → 保留旧版

### 3.4 上传器（开发者侧）

- 登录（账号 + 密码，本地保存）
- `ensure_folder(path)`：按路径逐级找/建文件夹（**已存在的复用，不重复建**）
- 只传差异：新增 + 更新；删除可选
- 上传前先传 manifest 的临时副本，全部成功后再替换正式 manifest（**保证线上永远是一个完整版本**）
- 完成后 `task=18` 取分享链接 + 密码，一键复制

### 4.4 打包格式与类型标记

**统一用 `.zip`**（蓝奏不接受奇怪扩展名，`.fgcpack` 也容易让人误解）。

文件夹型枪包上传前打包成 `X.zip`，**在 manifest 里标记类型**：

```json
{"path": "X.zip", "type": "folder", "target": "X",
 "size": 41943040, "sha256": "9f2c…"}
{"path": "Y.zip", "type": "zip",
 "size": 52428800, "sha256": "7d1a…"}
```

| type | 含义 | 下载后 |
|---|---|---|
| `zip` | 原生 zip 枪包 | 原样放入 |
| `folder` | 文件夹型枪包（已打包） | 自动解压到 `target` 目录 |

- 打包必须**确定性**：条目按名排序、时间戳归零、压缩级固定 → 同一内容永远同一 sha256
- 若预设里同时存在 `X/` 和 `X.zip`，文件夹型打包成 `X.folder.zip`（`target` 仍为 `X`），避免云端重名

## 五、UI 改造

### 5.0 两套界面，同一套引擎

身份是**全局**的，切换时整块界面换形态，但底层是同一套数据与引擎。

| 区域 | 玩家界面 | 开发者界面 |
|---|---|---|
| 侧边栏底部 | 「玩家」徽标 + [切换身份] | 「开发者」徽标 + 账号名 + [切换身份] |
| 主界面左列 | Step1 整合包 / Step2 预设 / Step3 详情 | 同左，但 Step3 变成「发布面板」 |
| 预设卡片 | 状态点 + 版本 + [更新] | 状态点 + 版本 + [发布] |
| 预设齿轮 | 分享链接 + 密码 + [测试连接] | 云盘路径 + [扫描差异] |
| 详情标签 | 概览 / 枪包 / 来源 | 概览 / 枪包 / 发布 / 历史 |
| 顶部动作 | [检查全部更新] | [全部扫描] + [批量发布] |

切换动效：沿用现有的幕布/滑块体系，切换时卡片内容做一次轻量重排（不整页闪）。



### 5.1 预设列表：从「窄条」变成卡片

现在：`Listbox` 一行一个名字，信息量几乎为零。

改成**卡片列表**（垂直滚动），每张卡片：

```
┌─────────────────────────────────────────────┐
│ ● SSR预设包                       [已应用]   │
│   v2026.10.18 · 24 个枪包 · 1.8 GB           │
│   ⟳ 有 3 个更新（共 142 MB）      [更新] [⋯] │
└─────────────────────────────────────────────┘
```

- 左侧状态点：绿色=已应用且最新，橙色=有更新，灰色=未应用，红色=源失效
- 右侧按钮随状态变化：`更新` / `已最新` / `绑定源` / `重试`
- `⋯` 打开详情

### 5.2 预设详情：右侧抽屉 / 面板

三个标签页：

| 标签 | 内容 |

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 蓝奏接口变更 | provider 隔离；域名池；失败降级到手动导入 |
| 免费额度/限速 | 单文件 100MB 上限（枪包 30–60MB 安全）；分批上传 |
| 大文件传输中断 | 重试 3 次 + 换域名；不支持 Range 就整包重下 |
| 上传中断留下半成品 | manifest 最后替换；失败不动正式文件 |
| 账号密码安全 | 只存本机；只在登录蓝奏时使用 |
| 云端被误改 | 每次同步前校验 manifest 结构；保留上一版可回滚 |
| 预设被本地改动 | 差异面板里明确标「本地独有」，默认不删除 |

## 九、需要你确认的决策点

1. **版本号格式**：日期式（`2026.10.18`）还是语义化（`1.4.0`）？我倾向日期式，发布简单。
2. **云端路径**：默认 `/PulsesSwap/<预设名>` 可以吗？
3. **移除的枪包**：默认「保留本地、标记为本地独有」，还是直接删？
4. **自动检查更新**：默认开启还是关闭？
5. **保留几个旧版本**：默认 1 个（占双倍空间）。
6. **导出按钮**：确认直接移除「导出预设包 / 导出增量更新」，只保留本地导入兜底？
