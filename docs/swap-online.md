# Swap-Online 完整方案

> 分支：`feature/online`
> 一句话：**预设绑定一个云端源，双方各自维护 manifest，比对 manifest 就知道谁缺什么，只传/只下变化的部分。**

---

## 0. 名词

| 词 | 含义 |
|---|---|
| 预设 | 一组枪包的集合，本地一个目录 |
| 源 | 预设绑定的云端位置（蓝奏分享链接 + 密码） |
| manifest | 一份 JSON，描述预设里有哪些文件（路径 / 大小 / sha256 / 类型） |
| 本地 manifest | 程序扫描本地预设目录算出来的 manifest |
| 云端 manifest | 开发者发布时自动生成并上传的 manifest |
| 身份 | 全局角色：玩家 / 开发者 |

---

## 1. 范围

**做**

- 预设绑定云端源，一键检查更新、增量同步
- 开发者认证后一键发布（只传差异），自动产出分享链接和密码
- 两套界面（玩家 / 开发者），全局身份切换
- 打包/解包、校验、错误处理、进度反馈

**不做**

- 不做服务端、不做账号体系（只有蓝奏账号）
- **不做玩家端回滚**（已确认不需要）
- 不做静默自动更新（所有传输都要人确认）
- 不接管游戏启动

---

## 2. 角色与身份

**身份是全局的**，不是每个预设各一个。

| 身份 | 解锁条件 | 能力 |
|---|---|---|
| 玩家 | 默认 | 绑定源、检查更新、同步、删除本地多余（询问后） |
| 开发者 | 填蓝奏账号 + 密码并登录成功 | 上传、发布、删除云端多余、查看发布记录 |

- 认证信息存本机配置，带「退出认证」
- 未认证点「切换为开发者」→ 弹认证框，失败给明确原因（账号未激活 / 密码错 / 网络）
- 切换是界面级的，不改数据；切回玩家后开发者入口隐藏、配置保留

## 3. 数据模型

### 3.1 manifest

```json
{
  "schema": 1,
  "name": "SSR预设包",
  "version": "2026.10.18",
  "generation": 7,
  "min_app": "2.5.0",
  "generated_at": "2026-10-18T01:00:00Z",
  "notes": "新增 3 把枪，修贴图",
  "files": [
    {"path": "gun_alpha.zip", "type": "zip",    "size": 41943040, "sha256": "9f2c…"},
    {"path": "gun_beta.zip",  "type": "folder", "target": "gun_beta",
     "size": 52428800, "sha256": "7d1a…"}
  ]
}
```

| 字段 | 说明 |
|---|---|
| `schema` | 只增字段不改语义；高于程序支持版本时提示升级 |
| `version` | 展示用版本号（默认日期式） |
| `generation` | 每次发布自增；客户端结束时校验，防止装出半新半旧 |
| `min_app` | 低于此版本的程序提示先升级 |
| `files[].path` | **相对路径**（支持子目录），作为唯一键 |
| `files[].type` | `zip` 原样 / `folder` 需解压 / `file` 其他 |
| `files[].target` | 仅 `folder` 用：解压到哪个目录 |
| `files[].sha256` | 唯一可信标识 |

### 3.2 本地状态目录

```
PulsesSwap_database/online/
├── sources.json               每个预设绑定的源（URL / 密码 / 上次版本）
├── cloud/<preset>.json        上次拉到的云端 manifest（离线可用 + 变更对比）
├── local/<preset>.json        上次算出的本地 manifest（哈希缓存也在这）
└── staging/<preset>/          下载暂存（安装成功才动正式目录）
```

**不做玩家回滚**，所以没有 backup 目录。

### 3.3 源配置

```json
{"preset": "SSR预设包",
 "lanzou": {"url": "https://xxx.lanzoul.com/bXXXX", "password": "28pm"},
 "cloud_path": "/PulsesSwap/SSR预设包",
 "auto_check": true}
```

- 玩家只填 `lanzou`；开发者只填 `cloud_path`（账号是全局认证的）
- `auto_check` 默认开启：启动时后台检查，有更新在预设卡片显示角标

## 4. 差异引擎

### 4.1 两方比对（最终定稿）

只比 **本地 manifest** 和 **云端 manifest**，不做三方比对。

| 本地 | 云端 | 玩家 | 开发者 |
|---|---|---|---|
| 无 | 有 | **补齐**：下载 | **删除**：从云端移除 |
| 有 | 有，哈希相同 | 跳过 | 跳过 |
| 有 | 有，哈希不同 | **更新**：下载覆盖 | **更新**：上传覆盖 |
| 有 | 无 | **询问是否删除**（默认保留） | **必须上传**（可单项取消） |
| 本地损坏 | 有 | **重下** | 不适用（开发者本地永远最新） |

### 4.2 动作词表

`download / upload / skip / delete_cloud / delete_local / ask_delete_local / repair / blocked`

### 4.3 打包与类型

统一用 `.zip`（蓝奏不接受奇怪扩展名）。文件夹型枪包上传前打包，**类型写在 manifest 里**：

| type | 上传时 | 下载后 |
|---|---|---|
| `zip` | 原样 | 原样放入 |
| `folder` | 打包成 `X.zip`（确定性：条目排序、时间戳归零、压缩级固定） | 解压到 `target` |
| `file` | 原样 | 原样 |

同名冲突（预设里同时有 `X/` 和 `X.zip`）→ 文件夹打包成 `X.folder.zip`，`target` 仍是 `X`。

### 4.4 边界规则

| 规则 | 处理 |
|---|---|
| 云端有、manifest 没列的文件 | 视为**未托管**（如 description.txt），完全忽略 |
| 路径大小写 | 比较时不敏感，显示保留原样 |
| 非法文件名 / 超长 | 标红，不进入传输 |
| 单文件 > 100MB | 标红「超过网盘上限」，建议分卷 |
| 磁盘空间不足 | 下载前整体预检查，直接拒绝开始 |
| 忽略文件 | `.DS_Store` / `Thumbs.db` / `*.tmp` / 隐藏文件 |

### 4.5 输出结构

```python
Plan(role="player", items=[DiffItem(path, action, local_sha, cloud_sha,
                                    size, reason)], totals={...}, blocked=[...])
```

## 5. 玩家流程

```
① 预设齿轮 → 填分享链接 + 密码 → [测试连接]
      成功：显示云端版本 / 文件数 / 总体积
② [检查更新] → 下载云端 manifest（几十 KB）→ 与本地 manifest 比对
      2GB 预设也 <1 秒（不列云端文件、不算云端哈希）
③ 差异确认框
      新增 2 · 更新 1 · 本地多余 0 · 一致 21 · 合计下载 142 MB
      逐项可勾选；本地多余项单独列出并询问「是否删除」（默认保留）
④ 开始同步
      列一次云端文件（拿 file_id）→ 逐个下载 → 逐包校验 sha256
      进度：当前文件 + 总进度 + 速度 + 预计剩余
⑤ 安装
      下载到 staging → 校验 → 解压/放入 → 原子替换正式目录
⑥ 完成
      更新本地 manifest 与云端 manifest 存档；提示「已同步到 v2026.10.18」
```

**失败处理**

| 失败点 | 处理 |
|---|---|
| 拉 manifest 失败 | 用上次的云端 manifest，界面标「离线」 |
| 分享密码错 | 明确提示，引导去齿轮里改 |
| 某个文件下载失败 | 换域名重试 3 次；仍失败则该包标记失败，其余继续 |
| 校验不符 | 重下一次；仍不符标记失败并提示 |
| 中途关程序 | staging 残留，下次启动清理；正式目录未受影响 |

## 6. 开发者流程

```
① 切换身份 → 认证（蓝奏账号 + 密码）→ 登录成功才解锁
② 预设齿轮 → 填云端路径（如 /PulsesSwap/SSR预设包）
③ [扫描差异]
      本地 manifest（现算）vs 云端 manifest
      新增 2 · 更新 1 · 一致 21 · 云端多余 0
④ 确认发布框
      版本号（默认日期）+ 更新说明
      逐项勾选（新增/更新默认全选，可取消）
      云端多余项：询问「删除云端」还是「保留」
      [预演] 只显示将做什么，不传输
⑤ 开始发布
      逐级确保文件夹存在（有就复用，不重复建）
      逐个上传（文件夹型先打包）
      进度同玩家侧
⑥ 替换 manifest
      所有文件上传成功后，最后上传 manifest（generation +1）
      失败则线上仍是完整旧版
⑦ 完成
      显示版本、文件数、体积
      自动取分享链接 + 密码 → 一键复制
```

## 8. UI 设计

### 8.1 两套界面

| 区域 | 玩家 | 开发者 |
|---|---|---|
| 侧边栏底部 | 「玩家」徽标 + [切换身份] | 「开发者」徽标 + 账号名 + [切换身份] |
| 预设卡片按钮 | [更新] | [发布] |
| 预设齿轮 | 分享链接 + 密码 + [测试连接] | 云盘路径 + [扫描差异] |
| 详情标签 | 概览 / 枪包 / 来源 | 概览 / 枪包 / 发布 / 记录 |
| 顶部动作 | [检查全部更新] | [全部扫描] + [批量发布] |

切换时卡片轻量重排（沿用现有幕布/滑块体系，不整页闪）。

### 8.2 预设卡片（取代现在的 Listbox 窄条）

```
┌─────────────────────────────────────────────┐
│ ● SSR预设包                       [已应用]   │
│   v2026.10.18 · 24 个枪包 · 1.8 GB           │
│   ⟳ 有 3 个更新（142 MB）        [更新] [⋯] │
└─────────────────────────────────────────────┘
```

状态点：绿=已应用且最新 / 橙=有更新 / 灰=未应用 / 红=源失效 / 蓝=未绑定源。

### 8.3 预设详情（三/四标签）

| 标签 | 内容 |
|---|---|
| 概览 | 版本、来源、上次同步、总体积、状态、[更新] |
| 枪包 | 卡片化列表：名字、大小、状态（一致/待更新/本地多余/损坏） |
| 来源 | 分享链接（密码打码）、[测试连接]、[更换源] |
| 发布/记录 | 仅开发者：云端路径、发布历史 |

### 8.4 同步框 / 发布框

同步框：差异列表（逐项勾选）+ 体积合计 + [取消][开始同步] → 进度页
发布框：版本 + 说明 + 差异列表 + [预演][开始发布] → 进度页 → 分享链接/密码一键复制

### 8.5 视觉

- 卡片 hover 描边（复用 `attach_hover_glow`）
- 状态点颜色过渡，不闪烁
- 进度条沿用现有曲线
- 同步中卡片显示细进度环，完成后短暂高亮
- 空状态 / 离线 / 错误各有明确视觉语言

## 9. 启动行为

1. 窗口先出来（不等扫描）
2. 后台线程扫描所有预设目录，**增量重算**本地 manifest：
   - 只取 `(路径, size, mtime)`，三者未变就沿用旧哈希
   - 2GB 预设无改动约 200ms
3. 扫描完刷新卡片状态
4. 若 `auto_check` 开启且身份为玩家 → 后台拉云端 manifest 比对，有更新给卡片加角标

## 10. 错误与异常

| 场景 | 提示与处理 |
|---|---|
| 蓝奏接口变更 | 「解析失败，可能是网盘接口调整」+ 诊断入口 + 手动导入兜底 |
| 分享失效/密码错 | 明确指出是哪一项，引导去齿轮修改 |
| 网络中断 | 保留已完成部分（staging），可续传未完成文件 |
| 磁盘不足 | 开始前预检查，提示需要多少空间 |
| 云端 manifest 结构异常 | 拒绝使用，保留上次的 |
| 程序版本过低 | 提示先升级软件 |
| 上传中断 | 线上 manifest 未替换，仍是完整旧版 |

## 12. 还差你确认的两点

**1. 玩家改过的同名文件怎么办？**
两方比对下，玩家手动改过的枪包（同名、哈希不同）会被判定为「更新」并被云端覆盖，
而且不做回滚 → **改动会丢**。

- 方案 A：接受（简单，符合"云端为准"）
- 方案 B：覆盖前把它挪到 `online/overwritten/<时间>/` 备份一份（不算回滚，只是防丢）

**2. 删除本地多余枪包时，删到回收站还是直接删？**
默认走系统回收站更安全，但 Tk 没有现成接口，需要调用系统命令。
