# 一键化重构清单（3.1）

目标：默认只让用户做“选对象 + 点一个按钮”，不让用户理解差异、版本号、线程、上传/下载方向。
软件选择最稳妥的默认方案；高级能力只在设置里开启。

## 一、操作盘点

### 已经是一键

| 操作 | 入口 | 说明 |
|---|---|---|
| 选择整合包 | 首页 / 拖入 | 选目录或拖入后自动定位 tacz |
| 一键替换 / 重新替换 | 首页主按钮 | 应用当前预设，确认一次 |
| 切换身份 | 侧栏 / 设置 / 管理 | 玩家 ↔ 开发者 |
| 登录 / 退出蓝奏 | 管理 / 设置 | 需要账号密码，登录本身一键 |
| 绑定云端来源 | 管理 | 需要分享链接/密码，保存一键 |
| 取消任务 | 进度条 | 仅可协作任务 |
| 页面切换 | 侧栏 | 带幕布动效 |
| 设置开关 | 设置 | 即时保存 |
| 选择数据库目录 | 设置 | 目录选择器 |

### 应该一键，但目前要用户决策

| 操作 | 现状 | 一键方案 |
|---|---|---|
| 玩家更新当前预设 | 先“检查更新”，再勾选差异，再“同步选中” | **一键更新**：自动检查 → 下载/修复 → 按“完全同步”设置清理本地多余 → 若该预设已应用则自动替换 |
| 玩家更新全部预设 | 无 | **一键更新全部**：遍历已绑定预设，逐个执行上面的流程，失败不阻塞其他预设 |
| 开发者发布当前预设 | 先生成计划，再填版本号/说明，再勾选，再发布 | **一键发布**：自动扫描 → 自动计划 → 自动递增版本 → 只上传新增/变更，保留云端多余（安全默认）→ 发布 |
| 开发者发布全部变更 | 无 | **一键发布全部**：遍历有本地变更的预设，逐个自动发布 |
| 开发者看“待上传” | 误显示“待下载” | 计划必须按 `plan.role` 渲染；开发者只出现“待上传/云端多余/一致” |

### 必须保留手动输入（无法一键）

| 操作 | 原因 |
|---|---|
| 选择整合包目录 | 需要文件系统位置 |
| 登录蓝奏 | 需要账号密码 |
| 绑定分享链接 | 需要用户提供链接/提取码 |
| 选择数据库目录 | 需要文件系统位置 |
| 新建/重命名预设 | 需要名称 |
| 删除预设 | 破坏性，保留确认 |

### 折叠到“高级操作”（默认关闭）

- 手动勾选差异条目
- 手动填写发布版本号 / 发布说明 / 最低版本
- 只生成发布计划、不发布
- 删除云端多余文件
- 发布前预览
- 完整更新前二次确认
- 手动“检查云端差异”入口

默认关闭时：差异只读展示，主按钮直接完成整套流程。
开启后：显示旧版的差异勾选和版本/说明表单，保留精细控制。

## 二、默认安全策略

1. 玩家一键更新只下载/修复，`ASK_DELETE_LOCAL` 按“完全同步”设置处理；删除走回收站。
2. 开发者一键发布只 `UPLOAD`，不自动 `DELETE_CLOUD`；云端多余文件保留，日志提示可用高级操作处理。
3. 一键发布版本号自动递增：优先云端版本，其次本地版本；`v1.0.4 → v1.0.5`。
4. 发布计划离线/读取失败时拒绝一键发布，避免用过期缓存覆盖云端。
5. 一键操作不弹确认框；只有删除预设等破坏性人工操作保留确认。
6. 一键更新若预设当前已应用，更新后自动重新替换；未应用则只更新预设文件。
7. 批量操作逐个执行，单个失败记录后继续，最终汇总“成功/失败”。

## 三、分阶段

1. 计划语义：`plan.role` 校验；开发者“待上传”；UI 绝不显示跨身份计划。
2. 设置：`advanced_actions` 默认 false；高级 UI 全部折叠。
3. 玩家：一键更新当前预设；失败/离线/无可更新都有明确结果。
4. 开发者：一键发布当前预设；自动版本、自动选择、不删云端。
5. 批量：玩家一键更新全部；开发者一键发布全部变更。
6. 实战测试：后端 fake/真实 service 流程、UI 黑盒、失败注入、双端截图。
7. 版本 3.1.0、文档、打包发布。

```text
开发一键上传全部: 发布完成 · 发布 2 个
玩家一键更新全部: 更新完成 · 更新 2 个

玩家增量一键更新: 更新完成 · 更新 1 个 · 已是最新 1 个

```
