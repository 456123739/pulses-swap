# Pulses Swap 真实联网全流程测试报告（v2.5.6）

> 测试时间：2026-10-19
> 账号：真实蓝奏云账号（本文不记录任何凭据）
> 云端目录：`SSR枪包预设`（只操作这个目录）
> 测试方式：全程通过 Swap 自己的界面完成，未使用浏览器/FTP 等外部工具代替

## 1. 环境与素材

| 项 | 内容 |
|---|---|
| 程序 | 源码运行（与发布包同一套代码），Linux + Tk 8.6 |
| 开发者环境 | `/tmp/ps_live/pack_dev`（独立数据库，空库起步） |
| 玩家环境 | `/tmp/ps_live/pack_player`（全新空库、空 tacz；另建 player2 做中断测试） |
| 整合包 | 仅含 `tacz/` 的模拟整合包 |
| 枪包 | 用户提供的两个 TACZ 枪包 ZIP（8.1 MB / 8.2 MB）+ 1 个自造文件夹型枪包 |
| 网络 | 真实蓝奏云登录、真实上传、真实下载、真实分享链接 |

两个角色通过两个独立目录/数据库隔离，开发者只把「发布完成后界面上的分享链接 + 密码」交给玩家，
玩家不知道开发者的本地目录与数据库。

## 3. Bug 列表

| ID | 描述 | 复现 | 修复 | 验证 |
|---|---|---|---|---|
| B1 | 玩家从云端添加后自动同步被「先应用该预设」拦截，首次拉取永远失败 | 全新玩家库 → 从云端 → 读取并创建 | 该规则只约束开发者发布；移除玩家 `_sync_now` 的 applied 守卫 | 阶段二完整下载并应用成功 |
| B2 | 云端添加的工作线程直接读 Tk 变量，抛 `main thread is not in main loop`，对话框永久「正在读取…」 | 点「读取并创建」 | 主线程先读密码再传参；来源页「测试连接」同样修复 | 阶段二添加成功 |
| B3 | 开发者「发布到云端」按钮一直 disabled（只有替换后的 busy 复位会放开），重启后点击无反应 | 开发者重启 → 选预设 → 点发布 | `publish_btn` 纳入按钮统一启停 | 阶段三发布成功；UI 自检断言 |
| B4 | 应用预设后索引不更新，下次启动误报「检测到新增 N 个」 | 应用新预设后重启 | 应用成功后按 tacz 重算索引 | 阶段三重启不再误报 |
| B5 | 详情里改版本后，主界面详情条仍显示旧版本 | 详情 → 改版本 → 保存 | 保存后刷新当前预设详情 | 阶段三显示 v1.1.0 |
| B6 | 同步/替换并发检查导致卡片显示「有 2 个更新」幽灵状态 | 同步完立刻应用 | 替换期间跳过检查；应用完成后自动复查 | 阶段二卡片回到「已是最新」 |
| B7 | 发布后分享链接只存顶层字段，来源页读不到；「发布完成」卡一关就找不到链接 | 发布成功 → 关闭卡片 → 打开来源页 | 同时写入 `lanzou.url/password` | 阶段一补充验证来源页回显 |
| B8 | 只读 tacz 下替换「静默半成功」：旧文件删不掉、新文件移进去、还标记已应用 | 只读 tacz → 一键替换 | 预检可写 + 清空/移动后校验 + 失败回滚标记 | 阶段五明确失败且状态不变；新增单测 |
| B9 | 以开发者身份重启后，设置页「数据库管理」（含强制校验）整块缺失 | 开发者退出 → 重启 → 设置 | 绑定数据库后按真实身份重建设置区 | 阶段一补充强制校验成功 |
| B10 | 「切换数据库」在独立模式下表面成功、实际重开整合包又回原库；`db_path` 未更新；合并模式被新库默认值冲掉 | 设置 → 切换数据库 | 独立模式明确拒绝；合并模式保留模式并更新当前会话 | 阶段五切换/切回通过 |

## 5. 遗留与建议

- macOS 仍无法在 CI runner 上跑 GUI 冒烟（无窗口服务器），mac 产物只在 Actions artifacts；
  Windows 构建由 CI 完成并在发布前做产物检查，本次未在 Windows 实机重跑 UI 流程。
- 网络中断用产品自身的「取消」模拟（上传/下载各一次），没有做物理断网；断网重连的
  重试仍依赖用户再点一次。
- 云盘免费账号单文件 100 MB 上限、扩展名白名单未变；本次文件均在上限内。
- 建议后续把「强制更新校验数据」从设置页挪到预设右键（当前入口太深，开发者不易发现）。
