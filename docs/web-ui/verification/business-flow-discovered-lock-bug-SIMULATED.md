# 实际 React 点击发现的清单读取日志锁问题（本地模拟数据）

2026-11-23 首传成功后，界面自动检查和后续 beta 增量发布均超时。该阶段尚未注入故障。

HTTP 模拟服务请求链已完整经过分享页、文件列表、文件页、iframe、apifile、下载页、ajax 和最终 `_pulses_manifest.cfg` 字节。

原始日志顺序：

```text
22:58:42 步骤 6/6：回写分享链接与发布记录
22:59:07 源不可用（http://127.0.0.1:<mock-port>/b1001）：读取云端内容超过 25 秒
22:59:07 启动检查跳过 模拟界面预设：读取云端内容超过 25 秒
22:58:42 通过网盘人机校验（127.0.0.1）
22:59:07 从预设 '模拟界面预设' 读取到 2 个枪包
22:59:33 读取云端 manifest 失败：读取云端内容超过 25 秒
22:59:08 通过网盘人机校验（127.0.0.1）
22:59:33 任务失败: 云端已经有文件，但读不到 manifest（分享页不可用）
```

原因：Controller 的 `_locked` 业务入口持有 `controller.lock`，`OnlineService._fetch_manifest_bounded` 启动单独线程并等待该线程；读取线程经 `LanzouShare` 的日志回调进入 `LogBus.log → controller.add_log`，尝试再次获取另一线程持有的 RLock，形成等待环。等读取超时后释放控制器锁，先前带旧时间戳的日志才被追加。已有 API 测试重新构造 OnlineService 时未传控制器日志回调，因此没有覆盖该死锁。

本测试始终保留真实日志连接，没有关闭日志或替换结果来规避。已向主代理报告，由主代理处理业务修复。本文件记录修复前实际发现；最终流程结果见 `business-flow-SIMULATED-report.json`。
