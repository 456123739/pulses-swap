# Pulses Swap 真实联网全流程测试报告

> 适用代码：2.5.6 起、最终修正于 2.5.8
> 测试日期：2026-10-19 · 平台：Linux + Tk 8.6（源码运行）
> 云端目录：仅 `SSR枪包预设` · 账号凭据不写入本文件
> 操作方式：全程通过 Swap 自己的界面完成，未用浏览器/FTP 等外部工具代替

## 1. 结论

- 在本次覆盖范围内（真实蓝奏云、开发者发布 → 玩家拉取 → 增量更新 → 边界异常），
  **全业务流程走通，未发现新的阻断级或数据损坏级问题**。
- 共修复 12 个问题（B1–B12）：其中 10 个是真实联调发现的阻断/半成品级缺陷，
  2 个是发布后复核发现的状态刷新问题。
- **不能声称「绝对无 bug」**，原因如实列在第 8 节：Windows/macOS 产物未在本机运行、
  没有做物理断网、角色隔离是体验级而非安全边界、冲突与部分卸载场景未覆盖。

## 2. 环境与角色隔离

| 项 | 内容 |
|---|---|
| 开发者环境 | `/tmp/ps_live/pack_dev`（独立数据库，空库起步） |
| 玩家环境 | `/tmp/ps_live/pack_player*`（全新空库、空 tacz） |
| 素材 | 两个 TACZ 枪包 ZIP（8.1 / 8.2 MB）+ 自造文件夹型枪包 |
| 网络 | 真实登录、上传、下载、分享链接 |

两个角色用两套目录/数据库隔离，开发者只把「发布完成后界面上的分享链接 + 提取码」
交给玩家，玩家不知道开发者的本地路径与数据库。**这是体验隔离，不是安全边界**：
同一台机器上仍可通过「切换身份」回到开发者（账号预填、密码取本机保存值）。

### 2.2 最终代码的真机复核（2.5.8）

发布器改完后重新用真实蓝奏云跑了一遍“改一个文件 → 发布 → 玩家更新”：

- 发布 v1.4.0 / generation 5：只上传 1 个 315 B 文件，网盘实际名
  `extra_gun.5e9a5f1f.zip`，同时按 id 删除了两条旧的同名 `extra_gun.zip`
- 玩家检查：1 个更新；同步 315 B；落盘为 `extra_gun.zip`，SHA-256 与开发者一致
- 这一轮也解释了上一轮“玩家校验失败”的真因：云端存在两条同名文件，旧 manifest
  按名字取到了旧的那条；现在 manifest 指向唯一名，不再有歧义

> 审查员的复现脚本里有几条“结论”是按旧行为写的（例如把恢复预设里的文件当成丢失、
> 只按 path 检查忽略 cloud 字段），这些已用新回归测试替代；确认的实际缺陷均在上表。

## 8. 边界、遗留与风险

1. **平台**：所有实测都在 Linux 源码运行。Windows 绿色版/安装包由 CI 构建并通过产物检查，
   但**没有在 Windows 实机启动过**；macOS job 卡在 GUI 冒烟（runner 无窗口服务器），
   **本版本没有任何 macOS 产物**。
2. **物理断网**未测：上传/下载中断是用产品自身的「取消」模拟的；上传取消只在**文件边界**
   生效（当前文件会传完，manifest 不替换），下载取消发生在 0 字节时，不代表中途断线。
3. **角色隔离是体验级**：同机可通过「切换身份」回到开发者；玩家来源页能看到自己预设的
   分享链接与密码（这是他从发布者那里拿到的信息）。
4. **未覆盖**：本地改过枪包后再同步的冲突提示/备份；删除「已应用/已绑定云端」的普通预设；
   Windows 文件被游戏占用、ACL、长路径；磁盘满；账号会话失效；合并模式切库后账号/绑定是否保留。
5. **云端测试数据**：`SSR枪包预设` 里留有 3 个 generation、约 16 MB 测试文件和一个分享链接，
   **未删除**——无法确认目录里是否有你原有的文件，贸然清理风险更大；需要清理请明确告知。
6. 证据未入公开仓库/发布包；如需第三方复核，可提供**脱敏后**的日志与截图。

## 15. 2.7.6 窗口出现 / 关闭动画

- 参考 PCL 主窗口的入场方式：出现时从下方 26px、alpha 0 开始，320ms 上浮淡入，末尾带轻微回弹；关闭时下移 18px、210ms 淡出，结束后 `withdraw()` + `quit()`。
- Tk 没有 WPF 的 `RenderTransform`，因此不做逐帧缩放：只改窗口 y 和 alpha，避免每次 geometry 尺寸变化触发整棵控件树重排。PCL 的旋转/缩放属于 WPF 合成层效果，Tk 下没有等价且不掉帧的实现。
- 启动时先画 alpha=0 的起始帧再启动补间，否则首次布局会把前几帧一起吞掉，用户看到的是窗口突然半透明出现。
- 开窗/关窗期间 `_on_opacity_event` / `_opacity_tick` 暂停 Win11 不透明刷新，防止中间帧 alpha 被拉回 1.0；动画结束再统一刷新。
- 修复隐藏状态下 `winfo_width()` 为 1 导致 `_center_window()` 按 1x1 计算、窗口显示后偏半个窗口的问题。
- 验证：`tests/test_window_motion.py` 8 个用例；`packaging/window_anim_check.py` 检查起始透明/位置、结束矩形、关闭淡出与隐藏；`startup_check` 等待开窗动画结束后再断言不透明和居中。
- 实测（Linux Xvfb，100%）：开窗在首次布局后约 40ms 启动，320ms 收束；关闭约 210ms 完成并隐藏。Windows 实机尚未逐帧验证，CI 只构建安装包；macOS 本期不构建。
