# Pulses Swap 真实联网全流程测试报告

> 适用代码：2.5.6 起、最终修正于 2.5.8
> 测试日期：2026-10-19 · 平台：Linux + Tk 8.6（源码运行）
> 云端目录：仅 `SSR枪包预设` · 账号凭据不写入本文件
> 操作方式：全程通过 Swap 自己的界面完成，未用浏览器/FTP 等外部工具代替

## 1. 结论

- 在本次覆盖范围内（真实蓝奏云、开发者发布 → 玩家拉取 → 增量更新 → 边界异常），
  **全业务流程走通，未发现新的阻断级或数据损坏级问题**。
- 共修复 12 个问题（B1–B12）：其中 10 个是真实联调发现的阻断/半成品级缺陷，
  2 个是发布后复核发现的状态刷新问题。
- **不能声称「绝对无 bug」**，原因如实列在第 8 节：Windows/macOS 产物未在本机运行、
  没有做物理断网、角色隔离是体验级而非安全边界、冲突与部分卸载场景未覆盖。

## 2. 环境与角色隔离

| 项 | 内容 |
|---|---|
| 开发者环境 | `/tmp/ps_live/pack_dev`（独立数据库，空库起步） |
| 玩家环境 | `/tmp/ps_live/pack_player*`（全新空库、空 tacz） |
| 素材 | 两个 TACZ 枪包 ZIP（8.1 / 8.2 MB）+ 自造文件夹型枪包 |
| 网络 | 真实登录、上传、下载、分享链接 |

两个角色用两套目录/数据库隔离，开发者只把「发布完成后界面上的分享链接 + 提取码」
交给玩家，玩家不知道开发者的本地路径与数据库。**这是体验隔离，不是安全边界**：
同一台机器上仍可通过「切换身份」回到开发者（账号预填、密码取本机保存值）。

## 2.1 第二轮独立黑盒审查（未告知任何“已修复”信息）

把当前代码复制成**无 git 历史**的干净副本，交给一个**不知道修复内容**的审查员，
要求它按“这软件一定有很多 bug”去找，不信任文档和现有测试。它确认了 14 个问题，
全部修复并补了回归测试：

| # | 问题 | 修复 |
|---|---|---|
| B13 | 发布先删云端旧文件再上传；失败/取消后旧 manifest 引用已删文件，**所有玩家同步失败** | 改为「只上传 → 换 manifest → 最后清理旧文件」；manifest 失败自动恢复旧版；取消清理未引用上传 |
| B14 | 勾选时去掉某项，manifest 仍宣告它 | manifest 按“发布完成时云端真实状态”拼，未上传的新文件不写入 |
| B15 | 同名上传被网盘改名后，manifest/下载仍按旧名找文件 | manifest 增加 `cloud` 实际文件名，下载器按 `cloud` 取、按 `path` 落盘 |
| B16 | 没有 applied 标记时替换会**永久删除** tacz 里的用户枪包 | 先把未归属枪包收进「恢复的枪包 <时间>」预设，再继续替换 |
| B17 | 改名失败后 applied/current 被清掉，后续替换会删掉原枪包 | 改名改为“先改目录、最后改状态”，失败只回滚目录 |
| B18 | 预设名可含 `../`、绝对路径、系统保留名，可从云端 manifest 触发任意目录写入 | 统一名称校验（拒绝分隔符/绝对路径/点开头/保留名），云端名字做 sanitize |
| B19 | 部分同步失败仍把版本推进到云端新版本 | 只有全部成功才更新 index/version |
| B20 | 替换进行中还能点「同步更新」，并发写 tacz | 同步/发布进入统一 busy 态，禁用同步/发布/替换，并拒绝并发入口 |
| B21 | 90 秒超时定时器不复位，会误杀下一次检查、清掉挂起的同步/发布 | 每次检查带自增 run id + 定时器，完成即取消，超时只作用于自己那次 |
| B22 | 合并/迁移数据库把 applied 标记一起带进来，一个库多个“已应用” | 合并/迁移重置 applied；加载时发现多个 applied 全部重置 |
| B23 | 发布成功后本地版本不变；一键发布清空更新说明/最低版本 | 发布成功同步 index/version；一键发布沿用上次 notes/min_app |
| B24 | 发布历史记录的是上一次的更新说明 | 改为记录本次 manifest 的 notes |
| B25 | 关闭整合包后「同步 N 项更新」按钮残留 | 关闭时隐藏并复位同步按钮/辅助行 |
| B26 | 删除预设不解除云端绑定/不清缓存，同名新预设继承旧源；改名不覆盖目标旧缓存 | 删除时 `forget_preset` 清 sources/manifest/staging；改名覆盖目标缓存 |
| B27 | 设置页改身份不刷新界面；来源页无法清除云端绑定 | 保存后按新身份重刷；新增「清除云端绑定」 |
| B28 | 发布/同步期间允许退出或关闭整合包 | busy 期间拒绝退出/关包/切换，避免半安装 |
| B29 | 合并覆盖时旧目录删不干净会混入新预设 | 删除不干净就跳过并报错 |
| B30 | 替换失败后卡片仍显示「已应用」 | 失败后刷新列表/详情 |
| B31 | 蓝奏允许同名文件共存；按名字下载会拿到旧的那一条（真机实测：extra_gun.zip 313B/314B 两条，玩家下到旧版） | 每次上传用内容指纹唯一名（如 `extra_gun.5e9a5f1f.zip`），manifest 写 `cloud`，按 id 清理旧文件（含同名重复） |

### 2.2 最终代码的真机复核（2.5.8）

发布器改完后重新用真实蓝奏云跑了一遍“改一个文件 → 发布 → 玩家更新”：

- 发布 v1.4.0 / generation 5：只上传 1 个 315 B 文件，网盘实际名
  `extra_gun.5e9a5f1f.zip`，同时按 id 删除了两条旧的同名 `extra_gun.zip`
- 玩家检查：1 个更新；同步 315 B；落盘为 `extra_gun.zip`，SHA-256 与开发者一致
- 这一轮也解释了上一轮“玩家校验失败”的真因：云端存在两条同名文件，旧 manifest
  按名字取到了旧的那条；现在 manifest 指向唯一名，不再有歧义

> 审查员的复现脚本里有几条“结论”是按旧行为写的（例如把恢复预设里的文件当成丢失、
> 只按 path 检查忽略 cloud 字段），这些已用新回归测试替代；确认的实际缺陷均在上表。

## 8. 边界、遗留与风险

1. **平台**：所有实测都在 Linux 源码运行。Windows 绿色版/安装包由 CI 构建并通过产物检查，
   但**没有在 Windows 实机启动过**；macOS job 卡在 GUI 冒烟（runner 无窗口服务器），
   **本版本没有任何 macOS 产物**。
2. **物理断网**未测：上传/下载中断是用产品自身的「取消」模拟的；上传取消只在**文件边界**
   生效（当前文件会传完，manifest 不替换），下载取消发生在 0 字节时，不代表中途断线。
3. **角色隔离是体验级**：同机可通过「切换身份」回到开发者；玩家来源页能看到自己预设的
   分享链接与密码（这是他从发布者那里拿到的信息）。
4. **未覆盖**：本地改过枪包后再同步的冲突提示/备份；删除「已应用/已绑定云端」的普通预设；
   Windows 文件被游戏占用、ACL、长路径；磁盘满；账号会话失效；合并模式切库后账号/绑定是否保留。
5. **云端测试数据**：`SSR枪包预设` 里留有 3 个 generation、约 16 MB 测试文件和一个分享链接，
   **未删除**——无法确认目录里是否有你原有的文件，贸然清理风险更大；需要清理请明确告知。
6. 证据未入公开仓库/发布包；如需第三方复核，可提供**脱敏后**的日志与截图。
