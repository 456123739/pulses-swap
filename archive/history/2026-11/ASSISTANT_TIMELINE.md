## 2026-10-07 21:21

「六条一起修完了」v2.4.2：https://github.com/456123739/pulses-swap/releases/tag/v2.4.2

**1. Win11 半透明（你最后那条线索直接把真因锁死了）**
「有弹窗在前面就变透明」= 窗口失焦时系统才上 Mica。真因是 `DWMWA_SYSTEMBACKDROP_TYPE` 我原来写的是 **0(AUTO)** —— AUTO 交给系统决定，失焦时它自己就上 Mica/Acrylic，壁纸就透进来了。改成 **1(DWMSBT_NONE)**，另外把未公开的 `DWMWA_MICA_EFFECT(1029)` 也显式关掉兜底。

**2. 字又小又糊**
两个原因叠一起：
- **糊**：进程没声明 DPI 感知 → Windows 把窗口位图整体拉伸。CTk 自己会声明，但它在「第一个控件创建时」才做，那时窗口已经按未感知状态建好了 —— 所以我在 `main()` 里**创建窗口之前**就声明（`SetProcessDpiAwareness(2)`）。
- **小**：字号整体 +1~2pt（TINY 10→11、SMALL 11→12、BODY 12→13、SUBHEAD 13→15、TITLE 15→17），并且自绘 Canvas 的几何/字号、grid minsize、Listbox 字号都按 CTk 的缩放系数同步放大 —— 不然 125%/150% 下 CTk 控件会放大而 Canvas 不会，两边错位。

**3. 报错很多 → 抓到一个真 bug**
`root.after()` 从 worker 线程调用会抛 `RuntimeError: main thread is not in main loop`。加载预设的线程正好这么写，**线程当场死掉 → UI 永远卡在「加载中」**，日志里一路报错。改成线程安全的队列投递（`ui_call()` + 主线程 25ms 轮询），29 处调用点统一替换。

**4. 「本次启动不再提醒」勾了没用**
原来只在点「确定 / 导出增量更新」时才读勾选框 —— 用 ESC 或窗口 ✕ 关掉就白勾了。现在 `wait()` 返回后统一读一次，**不管怎么关都生效**。（另外你截图里那个带标题栏和 ✕ 的弹窗是**独立窗口**，那是旧版的兜底路径；现在这个提醒是窗口内覆盖层。）

**5. 文件夹选择界面**

# 线上枪包分发方案（v1 设计稿）

## 一、结论

**用 123 网盘官方开放平台 API 做存储层，用一个签名 manifest 做唯一入口，客户端只认 manifest。**

不爬分享链接、不依赖网页、不依赖 GitHub。开发者推一次，其余全自动。

---

## 二、为什么是这个方案（排除法）

| 方案 | 致命问题 |
|---|---|
| GitHub Release | 单文件/仓库容量装不下 2GB 预设，**排除** |
| 爬 123 分享链接 | 需会话握手（我实测 5103）+ 验证码 + 流量校验，前端一改版就失效，**排除** |
| 手动传 + 手动下 | 不满足"无需操作"，**排除** |
| **123 官方开放 API** | 有文档、无验证码、支持列目录/拿直链/上传，**唯一同时满足"免费+快+可自动化"** |

关键实测依据（不是猜的）：

```
POST open-api.123pan.com/api/v1/file/list          → 200 {"code":401,"token is expired"}
POST open-api.123pan.com/api/v1/file/download_info → 200 {"code":401,...}
POST open-api.123pan.com/api/v1/share/list         → 200 {"code":401,...}
```
接口真实存在，只差 token。而 token 用 `client_id + client_secret` 换。

---

## 三、整体架构

```
开发者本地                    123 网盘                        好友的 Swap
─────────                    ─────────                       ──────────
tools/publish.py  ──上传──▶  /PulsesSwap/
  · 算 sha256                  manifest.json  ◀──拉取──┐
  · 生成 manifest              packs/…               │
  · (可选)签名                 └──────────────────┐   │
                                                 │   │
                                          download_info │
                                                 ▼   │
                                            枪包直链 ──┘
                                                 │
                                                 ▼
                                    校验 sha256 → 解包 → 原子替换
```

**三条铁律**（决定了这个方案不需要改）：
1. **manifest 是唯一入口**，客户端永远先读它，不猜文件名、不扫目录
2. **每个文件自带 sha256**，下载完必校验，坏了重下
3. **provider 可插拔**，今天 123、明天换阿里云盘，只加一个 provider，客户端不动

---

## 四、网盘目录规范（固定不变）

```
/PulsesSwap/
├── manifest.json                          ← 唯一入口，每次发布会覆盖
├── manifest.json.bak                      ← 上一版（发布失败可回滚）
└── packs/
    └── <pack_id>/                         ← 例：ssr
        ├── <version>/                     ← 例：1.4.0
        │   └── <pack_id>-<version>.fgcpack
        └── …                              ← 只保留最近 2 个版本
```

命名全部 ASCII + 版本号，避免中文路径在不同系统的编码问题（**这一点很重要**，枪包内部的文件名可以是中文，但云端路径不要）。

---

## 五、manifest 规范（schema v1）

```json
{
  "schema": 1,
  "channel": "stable",
  "generated_at": "2026-10-17T12:00:00Z",
  "min_app": "2.4.0",
  "packs": [
    {
      "id": "ssr",
      "name": "SSR预设包",
      "version": "1.4.0",
      "kind": "preset",
      "size": 2147483648,
      "sha256": "9f2c…",
      "file_id": 1234567,
      "path": "/PulsesSwap/packs/ssr/1.4.0/ssr-1.4.0.fgcpack",
      "notes": "新增 3 把枪，修复贴图错位",
      "mirrors": []
    }
  ],
  "sig": null
}
```

字段设计意图：

| 字段 | 为什么要有 |
|---|---|
| `schema` | 将来加字段不会把老客户端搞崩 |
| `min_app` | 老版本客户端能明确提示"请先升级软件"，而不是报个莫名其妙的错 |
| `file_id` | 官方 API 拿直链的主键（路径会变，fileId 不会） |
| `path` | fileId 失效时按路径重新查（双保险） |
| `sha256` + `size` | 校验 + 磁盘预检查 |
| `mirrors` | **现在就留好**，将来加别的源不用改客户端 |
| `sig` | 预留，见第十节 |

---

## 六、客户端流程（含每步失败处理）

```
① 读本地缓存 manifest（有则先展示，不阻塞 UI）
② 后台拉远端 manifest
     ├─ 网络失败 → 用缓存，界面标"离线"
     └─ 成功 → 校验 schema/min_app/sha256 结构 → 写入缓存
③ 比对：本地每个 pack 的 sha256 vs manifest
     ├─ 一致 → 跳过
     └─ 不一致/缺失 → 加入下载队列
④ 逐个下载（串行，避免打满带宽）
     ├─ download_info(file_id) 拿直链
     ├─ Range 断点续传（.part 文件 + .part.json 记录进度）
     ├─ 失败重试 3 次，间隔 2s/4s/8s
     └─ 完成后校验 sha256
         ├─ 不符 → 删除重下一次
         └─ 两次都不符 → 标记失败，跳过（不阻塞其它包）
⑤ 安装
     ├─ 解到 <db>/staging/<pack_id>/
     ├─ 校验内部结构（有 tacz/ 或 .fgcpack 索引）
     ├─ 旧的移到 <db>/backup/<pack_id>/<old_version>/
     └─ staging → 正式目录（同盘 rename，原子）
⑥ 收尾
     ├─ 更新本地 state.json（当前版本、校验和、时间）
     ├─ 保留 1 个旧版本用于回滚
     └─ 清理 .part 与 staging 残留
```

**任何一步失败都不影响已有数据** —— 下载和安装全程在暂存区，只有最后一步 rename 才动正式目录。


## 三、修了什么（按风险分组）

**发布链路（最严重的一类）**
- 改成「只上传 → 换 manifest → 最后清理旧文件」；上传失败自动恢复旧 manifest，取消会清理未引用的上传。**旧版再也不会因为发布失败而让所有玩家同步失败。**
- 每次上传用带内容指纹的唯一云端名（`name.<sha8>.ext`），manifest 记 `cloud`，下载器按 `cloud` 取、按 `path` 落盘。真机发现蓝奏会存成**两条同名文件**，按名字下载会拿到旧版——这是上一轮玩家校验失败的真因。

**替换预设（防丢文件）**
- tacz 里有没有归属的枪包、又没有 applied 标记时，先收进「恢复的枪包 <时间>」预设，再替换。

- 改名失败不再清掉「已应用」状态；预设名拒绝 `../`、绝对路径、保留名；云端名字也会 sanitize。

## 阶段 2：桥接层

**目标**：把 controller 变成稳定的 `js_api`，并保证线程安全。

**任务**

1. `Api.invoke(method, params)`：白名单、参数校验、权限守卫、统一错误信封。
2. `JobRunner`：提交、取消、进度、异常、清理；所有耗时操作后台执行。
3. `EventPump`：单线程消费事件队列，合并进度到 20–30Hz，单调 `seq`，窗口关闭安全退出。
4. DND：Python `window.dom` 的 `drop` 接收路径，React 只负责视觉；路径校验后再交给 controller。
5. 主窗口：原生标题栏、`min_size`、启动隐藏至首帧、关闭时任务保护。
6. 合同测试：每个 API 方法的成功/失败/超时/取消/重复提交。

**退出条件**

- API 调用在 50ms 内返回 jobId 或快照。
- 所有后台任务都有取消路径；关闭窗口不会留下线程。
- 事件乱序、重复、迟到 Job 事件不会污染前端。
- 原生文件夹选择、拖拽路径、身份守卫均有测试。

## 现在的检查逻辑

- 启动时只检查 **已绑定、未应用、且超过 15 分钟未检查** 的预设。
- 15 分钟内直接使用本地保存的云端 manifest，不重复请求网盘。
- 手动点击“检查差异/一键更新”始终强制走网络，不受节流影响。
- 已应用预设启动时跳过检查：它的文件在 `tacz` 里，普通扫描会误报“待下载”；用户点一键更新时会先收回再检查。
- 每个来源保存 `last_check` 时间，重启后仍然有效。

没有直接用蓝奏的“修改时间”作为判断依据，因为分享接口并不稳定提供 manifest 修改时间；直接依赖会漏更新。当前采用的是更稳的 **15 分钟 TTL + 本地 manifest 缓存**，不再频繁拉取。

## 代码位置

- `src/online/service.py`：`check(..., prefer_cache=True, cache_ttl=900)` 缓存快路径。
- `src/pulses_web/controller.py`：启动检查只挑过期且未应用的预设。
- `src/pulses_web/api.py`：新增 `online.auto.check`。
- `src/pulses_web/web/src/App.jsx`：启动时自动接上检查，设置文案改为“15 分钟内不重复”。
